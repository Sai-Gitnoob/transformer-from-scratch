## A Formal Definition

The paper defines attention precisely:

> An attention function maps a query and a set of key-value pairs to an output — where the query, keys, values, and output are all vectors. The output is a **weighted sum of the values**, and the weight given to each value is decided by a **compatibility function** between the query and its corresponding key.

That's dense on first read, so let's take it apart piece by piece — starting with the one term doing most of the work: the **compatibility function**.

---

## The Compatibility Function

The compatibility function answers exactly one question:

> **How well does this query match this key?**

Think of it like a search engine ranking results. You search *"I want space books"*, and the engine scores every book in the catalog against your search:

```
Query:  "I want space books"

Key 1: "astronomy and planets"  →  score = 0.90  (highly relevant)
Key 3: "space history"          →  score = 0.85  (highly relevant)
Key 2: "cooking recipes"        →  score = 0.02  (not relevant)
```

Every key gets a score. High score → the model should pay close attention to whatever that key is attached to. Low score → mostly ignore it.

That's it. That's the whole idea of "compatibility." In the Transformer specifically, this scoring is done with a **dot product** — a simple calculation that measures how aligned two vectors are — but the *concept* of a compatibility function is bigger than any one formula. (The next chapter shows exactly how the dot product produces those scores, step by step.)

## Putting Names to the Three Vectors: Q, K, V

Now we can properly define the three ingredients the formal definition mentioned — **query, key, and value** — using the same library search:

| Concept | Library Analogy | In Attention |
|---|---|---|
| **Query (Q)** | Your search request: *"I want books about space"* | The current word, asking *"who is relevant to me?"* |
| **Key (K)** | Each book's index tag: *"this book is about space"* | Every word, advertising *"here's what I'm about"* |
| **Value (V)** | The actual content inside the book | The actual information a word carries, ready to be used |
| **Output** | The books you actually walk away reading | A weighted blend of the most relevant values |

Notice the two-step nature of a library search: you don't read the *whole library* — you scan index tags (**keys**) against your search (**query**) first, decide what's relevant, and only then go get the actual content (**values**) from the best matches. Attention works in exactly that order.

---

## Bringing It Back to a Sentence

Recall the ambiguous pronoun from the story chapter:

> "The animal didn't cross the street because **it** was too tired."

In attention terms: **"it"** is the **query** — it's asking the rest of the sentence *"who are you, relative to me?"* Every other word offers up a **key** as its answer, gets scored by the compatibility function, and the words that score highest (like "animal") hand over their **value** — their actual meaning — to shape what "it" ends up representing.

No numbers yet — that's deliberate. This chapter is about understanding *what* Q, K, and V are and *why* the mechanism is structured this way. The next chapter picks up exactly here and shows you the real dot-product math, the scaling step, and the actual output.

---

> **One-line insight:** Attention isn't magic — it's a search. Every word searches the sentence for the most relevant context, using a query, a set of keys to compare against, and values to actually retrieve.
