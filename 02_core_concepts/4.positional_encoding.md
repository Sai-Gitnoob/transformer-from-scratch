## A Quick Prerequisite: Why Words Become Vectors

Before any of this, a word has to stop being a word. Computers can't reason about "happy" directly — so the Transformer first converts every token into a unique integer ID, then looks up a **dense vector** (a list of decimal numbers, as opposed to something sparse like a single ID) for it, using a learned **embedding layer**.

```
"happy" → token ID 7823 → [-0.31, 0.67, 0.14, ... ]  (512 numbers)
```

That vector has `d_model = 512` dimensions — the same 512 you've already seen show up in attention and the feed-forward layer. Every major component in the Transformer speaks in this same 512-dimensional "language," which matters because several operations (like the addition we're about to do) require vectors to be the exact same size to combine.

The key property: words with similar meaning end up with similar vectors, learned automatically during training — nobody hand-assigns these numbers.

That's all the embedding background we need. On to the actual problem.

---

## Why Do We Need Positional Encoding?

The Transformer has no recurrence and no convolution — it processes every word **simultaneously**. That's the whole point (parallelization!), but it comes with a side effect:

> **The model has no built-in sense of word order.**

Without some fix, the Transformer would see these two sentences as identical, since they contain the exact same set of words:

```
"The cat sat on the mat."
"The mat sat on the cat."
```

Obviously those mean very different things. So the model needs an explicit way to know not just *what* each word is, but *where* it sits in the sentence.

---

## The Core Idea

The fix: generate a **Positional Encoding (PE)** vector for each position, and simply **add it** to that word's embedding, before the combined vector enters the encoder or decoder:

$$\text{Final Input} = \text{Word Embedding} + \text{Positional Encoding}$$

Since this is an **element-wise addition** (each number added to the number in the same position), both vectors must be the same size — so the positional encoding is also 512-dimensional.

```
Word Embedding ("cat")     [0.20, 0.81, 0.13, ...]
                          +
Positional Encoding (pos=2) [0.91, 0.40, 0.72, ...]
                          =
Final Input                [1.11, 1.21, 0.85, ...]
```

That combined vector now encodes both **what the word means** and **where it appears**.

---

## The Formula

Rather than learning position vectors during training, the original Transformer generates them with a fixed formula built on sine and cosine waves:

$$PE_{(pos,\ 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right) \qquad PE_{(pos,\ 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

| Symbol | Meaning |
|---|---|
| `pos` | The word's position in the sentence (0, 1, 2, ...) |
| `i` | Which dimension-pair we're computing (0, 1, 2, ... up to 255) |
| `d_model` | 512 — the embedding size |
| Even dimensions (`2i`) | Computed with **sine** |
| Odd dimensions (`2i+1`) | Computed with **cosine** |

In words: **every position gets its own unique combination of sine and cosine values, spread across all 512 dimensions.**

---

## Why Different Dimensions Move at Different Speeds

The `10000^(2i/d_model)` term in the denominator controls how fast each dimension's wave oscillates. Small `i` → fast-changing wave; large `i` → slow-changing wave:

| `i` | Denominator | Behavior |
|---|---|---|
| 0 | 1 | Very fast oscillation |
| 10 | ≈ 2.4 | Medium frequency |
| 255 | ≈ 9,980 | Very slow oscillation |

The paper describes these as forming a **geometric progression** (each step scales by a constant factor, like `2π, 4π, 8π...`) of wavelengths — meaning the 512 dimensions together capture position information at many different scales at once, from fine-grained local position to broad, long-range position.

**A clock analogy:** think of a clock with a second hand, minute hand, and hour hand, each moving at a different speed. No single hand tells you the exact time on its own — but combined, they pinpoint a unique moment. Positional encoding works the same way: 256 pairs of sine/cosine waves, each oscillating at a different speed, combine to give every position in the sentence a completely unique 512-number "fingerprint."

---

## Worked Example

Take the sentence *"I am happy"* — positions 0, 1, and 2. Computing just the first four dimensions of each word's positional encoding:

| Position | Dim 0 (sin) | Dim 1 (cos) | Dim 2 (sin) | Dim 3 (cos) |
|---|---|---|---|---|
| 0 ("I") | 0.000 | 1.000 | 0.000 | 1.000 |
| 1 ("am") | 0.841 | 0.540 | ≈0.840 | ≈0.541 |
| 2 ("happy") | 0.909 | −0.416 | ≈0.908 | ≈−0.414 |

*(Position 0 always produces `[0, 1, 0, 1, ...]` — that's not a coincidence; `sin(0) = 0` and `cos(0) = 1` regardless of dimension, so the very first word in any sentence always gets this same starting signature.)*

Notice every row is completely different — no two positions ever collide.

---

## Why Sine and Cosine, Specifically?

Three properties make this particular choice deliberate, not arbitrary:

1. **Bounded range.** Sine and cosine only ever output values between −1 and +1, so positional encodings can never blow up to huge numbers and destabilize the addition with the embedding.
2. **Uniqueness.** As shown above, every position gets a distinct combination — no repeats.
3. **Relative position becomes learnable.** This is the subtle but important one. The paper notes that for any fixed gap `k`, the encoding at `pos + k` can be written as a simple linear function of the encoding at `pos`. In practice, this means the model doesn't have to memorize "word 5" and "word 8" as unrelated facts — it can learn a general pattern like *"this word is three positions after that one,"* and that pattern transfers to any pair of positions the same distance apart, anywhere in the sentence.

---

## Fixed (Sinusoidal) vs. Learned Positional Encoding

The authors also tried treating positions like ordinary learned embeddings, and compared the two approaches:

| | Fixed (Sinusoidal) | Learned |
|---|---|---|
| How it's generated | Computed directly from the formula | Trained like any other parameter |
| Extra parameters | None | Yes |
| Generalizes past training length | Yes | No — limited to positions seen during training |
| Performance | Similar | Similar |

Both performed about equally well — but the fixed version won out for a practical reason: if the model is trained on sentences up to 100 words long but sees a 150-word sentence at inference time, the sinusoidal formula can simply be evaluated at position 150 with no issue. A learned embedding, by contrast, would have no vector for position 150 at all, since it never saw that position during training.

## Where This Fits in the Pipeline

```
Input Sentence  →  Token IDs  →  Word Embeddings (n×512)
                                        │
                                        │   +   Positional Encoding (n×512)
                                        ▼
                          Combined Representation (Meaning + Position)
                                        │
                                        ▼
                              Encoder / Decoder Stack
```

The decoder follows this exact same process for its own input tokens.

---

## Key Takeaways

| Concept | Purpose |
|---|---|
| Positional Encoding | Injects word-order information the Transformer otherwise lacks |
| Dimension | Matches the embedding size, `d_model = 512` |
| Formula | Sine on even dimensions, cosine on odd dimensions |
| Value range | Always between −1 and +1 |
| Key benefit | Every position gets a unique signature, and relative distances become learnable |
| Applied to | Both encoder and decoder inputs |

> **One-line insight:** Since the Transformer gave up recurrence to gain speed, it needed some other way to know word order — sine and cosine waves turned out to be a cheap, stable, and cleverly generalizable way to hand that information back.
