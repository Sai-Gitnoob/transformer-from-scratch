# Embeddings and Softmax

Before the Transformer can understand language, it must first convert words into numerical representations that a neural network can process. Likewise, after generating an internal representation of the next word, it must convert that representation back into an actual word.

This section explains how the Transformer performs these two tasks using **embeddings**, a **linear transformation**, and the **softmax function**.

---

# 1. From Words to Vectors: Embeddings

Computers cannot directly understand words like humans do.

For example, consider the sentence:

```
"I am happy"
```

Initially, every word is represented only by a unique integer ID.

| Word | Token ID |
|------|----------|
| I | 4521 |
| am | 892 |
| happy | 7823 |

These IDs are simply identifiers—they carry **no semantic meaning**.

For instance,

- 4521 is not "closer" to 892 than it is to 7823.
- The numbers themselves tell the model nothing about language.

To solve this, the Transformer uses an **Embedding Layer**.

---

## What is an Embedding?

An embedding converts each token ID into a dense vector of size **d_model**.

In the original Transformer:

```
d_model = 512
```

So every word becomes a vector containing **512 learned numbers**.

Example:

```
"I"
↓

[0.24, -0.51, 0.88, ..., 512 values]
```

```
"happy"
↓

[-0.31, 0.67, 0.14, ..., 512 values]
```

Instead of representing words as arbitrary IDs, they are now represented as points in a **512-dimensional semantic space**.

Words with similar meanings naturally learn similar vectors.

Example:

```
happy  ≈ joyful
car    ≠ happiness
```

The model learns these embeddings automatically during training.


---

# 2. Why 512 Dimensions?

Throughout the Transformer, every token is represented using vectors of size **512**.

This value is called

```
d_model
```

It is one of the most important hyperparameters in the architecture.

Every major component uses this same dimensionality:

- Input Embeddings
- Positional Encodings
- Self-Attention
- Feed Forward Networks
- Decoder Outputs

Everything communicates using **512-dimensional vectors**.

This consistency is essential because operations such as residual connections require vectors to have identical dimensions.

---
# Positional Encoding

## Why Do We Need Positional Encoding?

One of the biggest differences between the Transformer and earlier sequence models is that the Transformer contains **no recurrence (RNN)** and **no convolution (CNN)**.

- RNNs naturally process words one after another, so they inherently know the order of words.
- CNNs process neighboring words using sliding windows, which also preserves positional information.

However, the Transformer processes **all words simultaneously** using self-attention. While this makes training highly parallelizable, it introduces a new challenge:

> **The model has no built-in understanding of word order.**

For example, consider the sentence:

```
The cat sat on the mat
```

Without positional information, the Transformer would only see the set of words:

```
{the, cat, sat, on, the, mat}
```

To the model, the following sentences would appear identical:

```
The cat sat on the mat
```

```
The mat sat on the cat
```

Although they contain the same words, their meanings are completely different.

Therefore, the Transformer needs an explicit way to encode the position of every word in the sequence.

---

# The Core Idea

The paper solves this problem by adding a **Positional Encoding (PE)** vector to every word embedding before it enters both the encoder and the decoder.

The final input becomes:

$$\text{Final Input} = \text{Word Embedding} + \text{Positional Encoding}$$


Since addition is performed element-wise, both vectors must have the same dimension.

For the original Transformer,

```
Embedding Dimension = d_model = 512
Positional Encoding Dimension = 512
```

Example:

```
Word Embedding ("cat")

[0.20, 0.81, 0.13, ..., 512 values]

+

Position Encoding (Position = 2)

[0.91, 0.40, 0.72, ..., 512 values]

↓

Final Input

[1.11, 1.21, 0.85, ..., 512 values]
```

The resulting vector now carries both:

- **What the word means**
- **Where the word appears**

---

# The Positional Encoding Formula

Instead of learning positional vectors, the original Transformer uses a fixed mathematical function based on sine and cosine waves.

The paper defines positional encoding as:

$$PE(pos, 2i) = \sin\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)$$

$$PE(pos, 2i+1) = \cos\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)$$


Although the equations look complex, each $$PE(pos, 2i) = \sin\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)$$

$$PE(pos, 2i+1) = \cos\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)$$

### Variable Explanations

| Symbol / Term | Meaning |
| :--- | :--- |
| $pos$ | Position of the word in the sentence |
| $i$ | Dimension index |
| $d_{\text{model}}$ | Embedding dimension (512 in the original Transformer) |
| Even dimensions ($2i$) | Use sine function |
| Odd dimensions ($2i+1$) | Use cosine function |

# Worked Example

Consider the sentence:

```
"I am happy"
```

The word positions are:

| Word | Position |
|------|----------|
| I | 0 |
| am | 1 |
| happy | 2 |

Instead of computing all 512 dimensions, let's compute only the first four dimensions.

### Position 0 ("I")

```
Dimension 0 : sin(0) = 0.000

Dimension 1 : cos(0) = 1.000

Dimension 2 : sin(0) = 0.000

Dimension 3 : cos(0) = 1.000
```

Result:

```
[0.000, 1.000, 0.000, 1.000, ...]
```

---

### Position 1 ("am")

```
Dimension 0 : sin(1) ≈ 0.841

Dimension 1 : cos(1) ≈ 0.540

Dimension 2 : ≈ 0.840

Dimension 3 : ≈ 0.541
```

Result:

```
[0.841, 0.540, 0.840, 0.541, ...]
```

---

### Position 2 ("happy")

```
Dimension 0 : sin(2) ≈ 0.909

Dimension 1 : cos(2) ≈ -0.416

Dimension 2 : ≈ 0.908

Dimension 3 : ≈ -0.414
```

Result:

```
[0.909, -0.416, 0.908, -0.414, ...]
```

Every position receives a completely unique 512-dimensional positional fingerprint.

---

# Why Use Sine and Cosine?

The paper deliberately chooses sine and cosine because they provide several mathematical advantages.

---

## 1. Values Stay in a Stable Range

Sine and cosine always produce values between

```
-1 and +1
```

This ensures positional encodings never become excessively large and can be safely added to word embeddings without destabilizing training.

---

## 2. Every Position is Unique

Each position generates a different combination of sine and cosine values.

Example:

```
Position 0

[0.000, 1.000, ...]

Position 1

[0.841, 0.540, ...]

Position 2

[0.909, -0.416, ...]

Position 50

Completely different pattern

Position 100

Completely different pattern
```

No two positions share the same encoding.

---

## 3. Relative Positions Can Be Learned

Perhaps the most important property is that sine and cosine preserve **relative distance**.

The model can learn relationships such as:

- this word is one position ahead
- this word is three positions behind
- these words are close together
- these words are far apart

without explicitly being told those distances.

This makes positional encoding useful not only for identifying absolute positions, but also for learning relative word relationships.

---

# An Intuition

Imagine looking at a clock.

- The **hour hand** changes slowly.
- The **minute hand** changes faster.
- The **second hand** changes even faster.

Together, these three hands uniquely identify a moment in time.

Positional encoding follows a similar idea.

Some dimensions change very slowly.

Some change moderately.

Others change very rapidly.

The combination of many frequencies creates a unique signature for every position in a sequence.

---

# Learned vs. Fixed Positional Encoding

The authors experimented with two approaches.

## Fixed Positional Encoding

Generated directly using the sine and cosine equations.

Advantages:

- No additional parameters
- Can naturally generalize to sequences longer than those seen during training

---

## Learned Positional Encoding

Treats position vectors like embedding vectors and learns them during training.

Advantages:

- Model learns position representations directly

Disadvantages:

- Introduces additional parameters
- Cannot naturally generalize to positions beyond the maximum training length

---

## Comparison

| Fixed Encoding | Learned Encoding |
|----------------|------------------|
| Generated mathematically | Learned during training |
| No extra parameters | Additional trainable parameters |
| Generalizes to longer sequences | Limited by training length |
| Used in the original Transformer | Tested but not adopted |

The authors observed that both methods achieved similar performance.

They ultimately chose the fixed sinusoidal encoding because it generalized better to longer sequences while requiring no additional parameters.

---

# Where Positional Encoding Fits

The positional encoding is added immediately after the embedding layer in both the encoder and decoder.

```
Input Sentence

"I am happy"

        │
        ▼

Token IDs

        │
        ▼

Embedding Layer
(3 × 512)

        │
        ▼

Positional Encoding
(3 × 512)

        │
        ▼

Element-wise Addition

        │
        ▼

Combined Representation
(Meaning + Position)

        │
        ▼

Encoder Stack
```

The decoder follows the same procedure before processing its own input tokens.

---

# Key Takeaways

| Concept | Purpose |
|----------|---------|
| Positional Encoding | Injects word-order information into the Transformer |
| Dimension | Same as embedding dimension (\(d_{model}=512\)) |
| Formula | Uses sine for even dimensions and cosine for odd dimensions |
| Values | Always remain between -1 and 1 |
| Benefits | Provides unique positions and enables learning of relative distances |
| Used In | Both encoder and decoder inputs |
