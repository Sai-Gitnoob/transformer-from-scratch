# Queries, Keys, and Values — The Math Behind Attention

*Last chapter left us with a question: how does a word actually calculate "how relevant" another word is? Here's the answer — and the actual formula the Transformer uses to do it.*


---

## A Quick Refresher: Q, K, V

Before the formula, a quick mental model for the three players involved:

- **Query (Q)** — what the current word is "asking for." Think of it as the word raising its hand and saying *"here's what I'm looking for."*
- **Key (K)** — what every word "offers" as a label for itself. Every word in the sentence has one, and it's what gets checked against the query.
- **Value (V)** — the actual content/information a word carries, which gets passed along once it's decided that word is relevant.

A quick analogy: imagine searching a library. Your search term is the **Query**. Every book's title/index card is its **Key** — that's what you compare your search against. Once you find a good match, the **Value** is the actual content inside that book — what you walk away with.

---

## The Formula

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

That looks dense, so let's unpack every symbol before walking through it:

- **`Q · K`** — a **dot product**: a simple math operation that multiplies matching elements of two vectors and adds them up. The bigger the result, the more "aligned" (similar) two vectors are — this is how the model measures relevance between a query and a key.
- **`K^T`** — the **transpose** of K (its rows and columns flipped). This is just a technical requirement for the matrix multiplication to line up correctly; it doesn't change the meaning of K.
- **`√d_k`** — the square root of the key dimension (a fixed size, like 64). This is the **scaling** step, explained below.
- **`softmax`** — a function that takes a list of numbers and turns them into a set of positive weights that all add up to 1 (like turning raw scores into percentages). Bigger input numbers get disproportionately bigger weights — softmax exaggerates the difference between a strong match and a weak one.

In short: **compare the query to every key, scale the results so they behave well, turn them into percentages, then use those percentages to blend the values.**

---

## Walking Through an Example

Take the sentence:

> "The cat sat on the mat because **it** was tired."

We want to figure out what **"it"** refers to.

### Step 1 — Compare the query against every key (dot product)

The query for "it" gets compared against the key for every word in the sentence:

| Comparison | Score |
|---|---|
| "it" vs "cat" | 8.5 (strong match) |
| "it" vs "tired" | 6.4 (medium match) |
| "it" vs "mat" | 3.2 (weak match) |
| "it" vs "sat" | 2.1 (weak match) |

In practice, this is done for every query and every key at once using **matrix multiplication** — a way of computing many dot products in a single, GPU-friendly operation, instead of one comparison at a time.

### Step 2 — Scale the scores

Each score is divided by `√d_k`. If `d_k = 64`, then `√64 = 8`:

| Raw score | Scaled score |
|---|---|
| 8.5 | 1.06 |
| 6.4 | 0.80 |
| 3.2 | 0.40 |
| 2.1 | 0.26 |

**Why bother scaling?** When the key dimension is large, raw dot-product scores can grow very large. Feeding very large numbers into softmax pushes it into a region where it becomes extremely "confident" — and in that region, the **gradient** (the signal used during training to know how to adjust the model's weights) becomes almost zero. This is called a **vanishing gradient**, and it effectively stalls learning. Dividing by `√d_k` keeps the numbers in a range where training stays stable.

### Step 3 — (Decoder only) Masking

If this were happening inside the *decoder*, there'd be an extra step here: certain scores get forced down to negative infinity so that, after softmax, they become exactly zero. This stops a word from "peeking" at words that come after it — necessary when the model is generating text one word at a time. The encoder skips this step entirely, since it's allowed to look at the whole sentence at once. (More on this in the encoder/decoder chapters.)

### Step 4 — Softmax

The scaled scores get converted into a clean probability distribution — a set of weights that add up to exactly 1:

| Word | Attention weight |
|---|---|
| cat | 0.65 |
| tired | 0.20 |
| mat | 0.10 |
| sat | 0.05 |

### Step 5 — Weighted sum of the Values

Finally, each word's **Value** vector gets multiplied by its weight, and all of them are added together:

$$\text{Output} = 0.65 \times V(\text{cat}) + 0.20 \times V(\text{tired}) + 0.10 \times V(\text{mat}) + 0.05 \times V(\text{sat})$$

The resulting representation of "it" ends up dominated by information from "cat" — exactly the correct answer to *"what does 'it' refer to?"* (a task called **coreference resolution**).

## Dot-Product vs. Additive Attention

The Transformer's approach — comparing Q and K with a plain dot product — isn't the only way to measure "relevance" between two words. There's an older alternative worth knowing about:

| | Dot-Product (Multiplicative) Attention | Additive Attention |
|---|---|---|
| How it scores | Direct dot product: `Q · K` | Feeds `Q` and `K` through a small neural network |
| Extra learnable parameters | None | Yes — the small network has its own weights |
| Speed | Fast — runs as efficient matrix multiplication | Slower, more computationally expensive |
| Behavior at small `d_k` | Performs similarly to additive | Performs similarly to dot-product |
| Behavior at large `d_k` (unscaled) | Degrades — pushed into the vanishing-gradient region described above | Stays stable |

This is exactly why the Transformer's version is called *scaled* dot-product attention — the scaling step is what lets it get the speed benefits of a simple dot product without the large-`d_k` instability that would otherwise favor additive attention.

## The Other Half: Feed-Forward Networks

Attention isn't the only thing happening inside each Transformer layer. Right after the attention step, every position passes through a small, identical two-layer network called the **position-wise Feed-Forward Network (FFN)**:

$$\text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2$$

*(`max(0, ...)` here is a **ReLU activation** — it simply zeroes out any negative values, which helps the network learn non-linear patterns.)*

The division of labor is clean:

- **Attention** = communication *across* tokens — words gathering context from each other
- **FFN** = computation *within* each token — individually refining whatever context it just gathered

Every word goes through the exact same FFN, applied independently and identically at each position. Together, attention and the FFN are the two core operations repeated in every layer of the Transformer.

## Why the Constant Path Length Really Matters

We touched on this in the last chapter, but it's worth grounding in how training actually works, since it explains *why* short paths aren't just a nice theoretical property.

Training a neural network involves two passes:

- **Forward pass** — information flows from input → model → prediction.
- **Backward pass** — once the model makes a prediction, the error is measured, and a correction signal (the **gradient**) flows *backward* through the network to update every weight along the way.

Here's the catch: **the longer that backward path, the weaker the signal tends to get by the time it reaches early layers** — again, the vanishing gradient problem. In an RNN, information (and later, the gradient correcting it) has to pass through every intermediate hidden state:

```
"trophy" → h1 → h2 → h3 → h4 → h5 → h6 → h7 → h8 → "it"
```

Path length here is **O(n)** — it grows with the sentence. Each hop is a chance for the signal to weaken.

Self-attention shortcuts this entirely:

```
"it" ──────────────────────────────────────► "trophy"
```

One direct connection. Path length is **O(1)**, regardless of sentence length — so the training signal stays just as strong for a word 50 positions away as it does for one right next door.

---

## The Catch: Restricted Self-Attention

Full self-attention isn't free, though. Because every word compares itself to every other word, its computational cost grows **quadratically** with sentence length — meaning if you double the sentence length, the cost roughly *quadruples*, not just doubles:

```
n = 10,000 words  →  10,000² = 100,000,000 comparisons
```

For very long documents, that becomes expensive fast. One fix is **restricted self-attention**: instead of comparing every word to every other word, each word only attends to a fixed nearby window of `r` words.

| | Full Self-Attention | Restricted Self-Attention |
|---|---|---|
| Complexity | O(n² · d) | O(r · n · d) |
| Path length | O(1) | O(n/r) |

You trade away some of that perfect O(1) connectivity for a much cheaper computation — a reasonable trade-off for long documents, where "words 9,000 apart" rarely need to talk directly anyway. This exact idea later inspired architectures built specifically for long documents, like **Longformer** and **BigBird**.

---

> **One-line insight:** Scaled dot-product attention is just "compare, scale, weigh, blend" — and that one small formula is doing all the work that used to take an RNN dozens of sequential steps.
