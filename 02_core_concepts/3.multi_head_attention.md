## Why Multiple Heads?
 
A single attention pass produces **one** weighted average across the whole sentence. That's useful, but it forces every type of relationship — grammar, meaning, position, cause and effect — to get blended into a single representation. Some nuance inevitably gets lost in the mix.
 
Multi-head attention's fix is simple: instead of running attention once, **run it several times in parallel**, each with its own independently learned lens. Each "head" gets to specialize — one might end up tracking grammatical structure, another semantic meaning, another long-range dependencies — and their outputs get recombined at the end into one richer representation.
 
---
 
## The Setup
 
The original Transformer uses this configuration:
 
- `d_model = 512` — the full dimensionality of each word's representation
- `h = 8` — the number of attention heads
- `d_k = d_v = d_model / h = 64` — each head works in a smaller, 64-dimensional slice
So instead of one attention operation looking at the full 512 dimensions, eight independent operations each look at a 64-dimensional slice.
 
---
 
## The Formula
 
$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) \cdot W^O$$
 
$$\text{head}_i = \text{Attention}(Q \cdot W^Q_i,\ K \cdot W^K_i,\ V \cdot W^V_i)$$
 
In plain terms: **each head first transforms Q, K, and V using its own learned projection matrices, runs ordinary scaled dot-product attention (from the last chapter) on that transformed version, and then all the head outputs get stitched back together and passed through one final projection.**
 
The `W` matrices are the "learned lens" for each head — projection matrices whose job is to reshape the input so that head can focus on a particular kind of relationship. Notation like `W ∈ R^(512×64)` just means "a grid of learnable numbers with 512 rows and 64 columns" — nothing more exotic than that.
 
| Matrix | Shape | Role |
|---|---|---|
| `W_Q_i`, `W_K_i` | 512 × 64 | Project Q and K into head *i*'s 64-dim subspace |
| `W_V_i` | 512 × 64 | Project V into head *i*'s 64-dim subspace |
| `W_O` | 512 × 512 | Recombine all 8 heads back into one 512-dim output |
 
---
 
## Walking Through the Shapes
 
To keep the matrix arithmetic easy to follow, let's use a short 3-word sentence: **"The cat sat."**
 
**Step 1 — Input.** Each word starts as a 512-dimensional vector, so Q, K, and V for the whole sentence each have shape `(3 × 512)`.
 
**Step 2 — Project per head.** Each head multiplies the input by its own projection matrices:
 
```
Head 1:  Q × W_Q_1 = Q1  (3×512)·(512×64) → (3×64)
         K × W_K_1 = K1  →  (3×64)
         V × W_V_1 = V1  →  (3×64)
```
 
This repeats independently for all 8 heads, each with its own learned matrices — meaning each head genuinely sees the sentence through a different lens.
 
**Step 3 — Attention per head.** Ordinary scaled dot-product attention runs inside each head:
 
```
head_1 = Attention(Q1, K1, V1)  →  (3×64)
head_2 = Attention(Q2, K2, V2)  →  (3×64)
   ...
head_8 = Attention(Q8, K8, V8)  →  (3×64)
```
 
**Step 4 — Concatenate.** All eight `(3×64)` outputs are joined side by side (**concatenation**: simply stacking vectors end-to-end):
 
```
Concat(head_1, ..., head_8) = (3 × 512)
```
 
The model is back to its original 512 dimensions — but now that 512-dimensional vector carries eight distinct perspectives instead of one blended one.
 
**Step 5 — Final projection.** The concatenated result passes through one last learned matrix, `W_O` (512×512), which intelligently mixes the eight perspectives into a single, unified output:
 
```
(3×512) × W_O(512×512) = Final Output (3×512)
```
 
---
 
## What Each Head Actually Learns
 
Let's return to our familiar sentence — *"The cat sat on the mat because it was tired"* — to see this conceptually. The heads aren't hand-assigned these jobs; they emerge naturally from training. But once trained, something like this pattern tends to appear:
 
| Head | Tends to focus on | For "it," attends most to |
|---|---|---|
| Head 1 | Grammatical subject | "animal"/"cat" |
| Head 2 | Cause and effect | "tired" |
| Head 3 | Positional proximity | nearby words |
| Head 8 | Long-range dependencies | words far earlier in the sentence |
 
A single head would have to average all of these signals into one blurry answer. Eight specialized heads let each relationship stay sharp, and the final projection combines them without losing that sharpness.
 
---
 
## The Computational Cost Insight
 
This might sound like 8× the work — but it isn't. Because each head operates on a *reduced* dimension (64 instead of 512), the total cost roughly balances out:
 
```
Single head, full dimension:   1 pass  ×  O(512)  ≈  O(512)
Eight heads, reduced dimension: 8 passes × O(64)   ≈  O(512)
```
 
The computational budget stays about the same as running one full-size attention pass — but the model comes away with **eight independent perspectives** on the input instead of one. That's the core efficiency argument for multi-head attention: you get specialization essentially for free.

## End-to-End Flow
 
```
         Q (n×512)     K (n×512)     V (n×512)
              |             |             |
    ┌─────────┼─────────────┼─────────────┼──────────┐
    │  Head 1  ×W_Q1       ×W_K1        ×W_V1         │
    │         Q1(n×64)   K1(n×64)    V1(n×64)          │
    │                  Attention                        │
    │              → head_1_out (n×64)                  │
    ├────────────────────────────────────────────────────┤
    │  Head 2 … Head 8  →  same process, own weights     │
    └────────────────────────────────────────────────────┘
                        |
                     Concat  →  (n × 512)
                        |
                     × W_O
                        |
              Final Output (n × 512)
```
 
---
 
## Single Head vs. Multi-Head, Side by Side
 
| Feature | Single-Head Attention | Multi-Head Attention |
|---|---|---|
| Number of attention passes | 1 | h (e.g., 8) |
| Dimension per pass | Full 512 | 64 per head |
| Relationships captured | Blended together | Specialized, per head |
| Signal clarity | Lower — one averaged view | Higher — multiple distinct views |
| Computational cost | Baseline | Roughly the same (parallelized) |
| Output dimension | 512 | 512 (after concatenation + `W_O`) |
 
---
 
> **One-line insight:** Multi-head attention doesn't add cost — it trades one blurry, full-width look at the sentence for eight sharp, specialized ones, then recombines them into something clearer than either approach alone.
