## 1. The One-Sentence Version

Every sequence-to-sequence model, Transformer included, follows the same basic shape:

$$x_1, ..., x_n \;\rightarrow\; z_1, ..., z_n \;\rightarrow\; y_1, ..., y_m$$

- `x` — the input sentence
- `z` — the encoder's internal understanding of it
- `y` — the generated output sentence (note: `n` and `m` don't have to match — input and output can be different lengths)

Using our recurring office-building analogy: the **encoder** is the research team, reading the input once and building a complete understanding (`z`). The **decoder** is the writing team, producing the output one word at a time, consulting the research team's notes at every step.

## 3. Scaling the Embeddings

Recall from Core Concepts: the input embedding turns each word into a 512-dimensional vector, and positional encoding adds another 512-dimensional vector on top of it. One detail we deferred until now: **before that addition happens, the paper multiplies every embedding by `√d_model`.**

$$\text{Scaled Embedding} = \text{Embedding} \times \sqrt{d_{model}} = \text{Embedding} \times \sqrt{512} \approx \text{Embedding} \times 22.6$$

**Why bother?** Positional encoding values are always small — bounded between −1 and +1, since they come from sine and cosine. Learned embedding values, especially early in training, can also start out small. Without scaling, the addition could end up dominated by position rather than meaning:

```
Without scaling:
  Embedding = 0.02,  Position = 0.80  →  Final = 0.82   (mostly position!)

With scaling:
  Embedding = 0.02 × 22.6 ≈ 0.45,  Position = 0.80  →  Final = 1.25   (balanced)
```

This one multiplication keeps word meaning and word position contributing roughly proportionately, instead of letting one silently drown out the other.

## 4. From Decoder Output to an Actual Word

After passing through all 6 decoder blocks, what you have is still just a 512-dimensional vector — not a word. Two more steps turn it into one.

### Step 1 — Linear transformation

The 512-dimensional vector is projected up to the size of the entire vocabulary — 50,000 words, in the original paper:

```
512 dimensions  →  50,000 raw scores (one per possible word)
```

These raw scores are called **logits**. They're not probabilities yet — they can be any real number, positive or negative:

| Word | Logit |
|---|---|
| मैं | 8.72 |
| वह | 2.31 |
| खुश | 1.45 |
| हूँ | 0.92 |

### Step 2 — Softmax

The same softmax function from Core Concepts converts these logits into an actual probability distribution — a set of numbers between 0 and 1 that sum to exactly 1:

| Word | Probability |
|---|---|
| मैं | 0.82 |
| वह | 0.09 |
| खुश | 0.05 |
| हूँ | 0.04 |

The model picks the highest-probability word — here, "मैं" — as its output, then repeats the entire process for the next position.

## 5. Weight Sharing: One Elegant Shortcut

Here's a detail that quietly saves a lot of parameters. The Transformer uses **three** weight matrices that look, on paper, like they'd need to be entirely separate:

1. The input embedding (word → vector)
2. The output embedding (word → vector, on the decoder side)
3. The pre-softmax linear layer (vector → word scores)

The paper ties all three together, reusing **one single learned matrix** for all of them. This works because of a simple shape observation: the embedding matrix has shape `vocabulary_size × 512`, and the linear layer needs shape `512 × vocabulary_size` — one is just the **transpose** of the other. The same learned "word ↔ vector" relationship can run in both directions.

**A useful analogy:** a bilingual dictionary doesn't need two separate books, one for English→Hindi and one for Hindi→English — the same underlying word-pair knowledge just gets read in reverse. Weight sharing applies that same idea here.

**Why it's worth doing:**
- Fewer total parameters to learn and store
- Keeps the input and output vocabularies representing words consistently, in the same vector space
- Acts as a mild regularizer, reducing overfitting

## 6. The Complete Flow

Putting every piece together, start to finish:

```
"I am happy"
      │
      ▼
Token IDs → Shared Embedding Matrix → 512-dim vectors
      │
      ▼
× √512  (scaling)
      │
      ▼
+ Positional Encoding
      │
      ▼
Encoder (× 6 blocks: self-attention → feed-forward)
      │
      ▼
z  (encoder output)
      │
      ▼
Decoder (× 6 blocks: masked self-attention → cross-attention → feed-forward)
      │
      ▼
Shared Linear Transformation (same matrix, transposed)
      │
      ▼
Softmax → probability distribution over ~50,000 words
      │
      ▼
"मैं" → "खुश" → "हूँ" → [END]
```

## 8. Key Takeaways

- The Transformer is `input → encoder (z) → decoder → output`, with attention doing all the heavy lifting instead of recurrence or convolution
- Embeddings are scaled by `√d_model` so word meaning doesn't get overwhelmed by positional information
- The decoder's final vector becomes a word via a linear projection to vocabulary size, followed by softmax
- Weight sharing lets the same matrix serve as the input embedding, output embedding, and pre-softmax projection — fewer parameters, more consistency
- Every design choice in this book — attention, multi-head splitting, positional encoding, residual connections — exists to answer one question the paper's title already gives away: attention really was all it needed.
