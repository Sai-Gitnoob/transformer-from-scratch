# The Encoder

*Time to assemble everything from `02_core_concepts` into an actual working piece of the Transformer. Think of the whole architecture as a two-floor office building: the **encoder floor** is the research team — they read the input sentence and build a complete understanding of it. The **decoder floor** is the writing team — they generate the output, one word at a time, using the research team's notes. This chapter covers the research floor.*

---

## 1. The Big Picture

The encoder is a stack of **N = 6 identical blocks**, one feeding directly into the next:

```
Input
  ↓
[Encoder Block 1]
  ↓
[Encoder Block 2]
  ↓
   ...
  ↓
[Encoder Block 6]
  ↓
Final Encoder Output (z)
```

**One important clarification**, since it's an easy misread: `N = 6` does *not* mean "layer 1 does self-attention, layer 2 does feed-forward, and so on." Every one of the 6 blocks is a complete, identical unit that contains *both* a self-attention step and a feed-forward step. Each block simply takes the previous block's output and refines it further — like six editing passes over the same paragraph, each one sharpening the understanding a little more:

```
Pass 1 → basic word relationships
Pass 2 → grammatical structure
Pass 3 → broader context
Pass 4 → deeper dependencies
Pass 5 → subtle patterns
Pass 6 → final, refined representation
```

---

## 2. Inside a Single Block

Each block has exactly two sublayers, and **both are wrapped the same way**:

```
Input (x)
  ↓
Multi-Head Self-Attention
  ↓
LayerNorm(x + Sublayer(x))
  ↓
Feed-Forward Network
  ↓
LayerNorm(x + Sublayer(x))
```

That wrapping pattern — **residual connection, then layer normalization** — is worth understanding on its own, since it repeats at every single sublayer in the entire Transformer (encoder and decoder alike).

### Residual Connections

$$\text{Output} = x + \text{Sublayer}(x)$$

Instead of letting each sublayer *replace* its input, the model adds the sublayer's output *on top of* the original input. The intuition: rather than risk losing the original signal every time it passes through a layer, the model always keeps a direct copy available and simply layers new information on top. This turns out to matter a lot for training — it helps gradients flow cleanly through many stacked layers (recall the vanishing-gradient issue from Chapter 2 of Core Concepts), which is part of what makes stacking 6 (or many more) layers practical at all.

### Layer Normalization

$$\text{LayerNorm}(x + \text{Sublayer}(x))$$

Applied right after the residual addition, this step rescales the values in each vector to keep them in a stable, consistent range before they move to the next sublayer. Think of it as good housekeeping between steps — it keeps numbers from drifting too large or too small as they pass through six stacked blocks, which stabilizes training.

The pattern is always the same order: **add, then normalize.**

---

## 3. Why Everything Stays 512-Dimensional

Every vector flowing through the encoder — embeddings, attention outputs, feed-forward outputs — keeps the same size: `d_model = 512`.

This isn't arbitrary. The residual connection `x + Sublayer(x)` is a direct element-wise addition, and addition only works if both sides are the same size. So the entire encoder is built around one consistent 512-dimensional "language" that every component speaks, purely so this addition never breaks.

---

## 4. Encoder Self-Attention

The first sublayer in each block is the multi-head self-attention you already met in Core Concepts — here, all three inputs (Q, K, V) come from the same place: the encoder itself, attending to its own previous layer's output.

```
Q  ←  encoder's previous layer
K  ←  encoder's previous layer
V  ←  encoder's previous layer
```

Crucially, **there is no masking here** — every word is free to attend to every other word in the sentence, regardless of whether it comes before or after. That's the "research team" doing an open discussion: nothing is hidden from anyone yet, because the whole point is to build the fullest possible understanding of the input before handing it off.

**Example** — *"The animal didn't cross the street because it was too tired"*:

```
"it"     → attends to: animal (0.65), tired (0.20), street (0.10), ...
"animal" → attends to: cross (0.40), street (0.30), didn't (0.20), ...
```

By the time the sentence has passed through all 6 blocks, every word's representation has absorbed context from the entire sentence — that fully "read" understanding is exactly what gets handed to the decoder.

## 5. The Feed-Forward Network (FFN)

The second sublayer is the position-wise FFN you saw introduced in Core Concepts:

$$\text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2$$

One detail worth adding here that we skipped earlier: the FFN doesn't just transform a 512-dimensional vector into another 512-dimensional vector directly — it **expands** first, then **compresses back**:

```
512  →  2048   (expand, via W1)
2048 →  apply ReLU (zero out negative values)
2048 →  512    (compress back, via W2)
```

This expand-then-compress pattern gives the network more room to work with in the middle step, before squeezing the result back down to the standard 512-dimensional size everything else expects.

As covered before: attention handles *communication* between words, while the FFN handles *computation* within each word individually — applied identically at every position, with its own learned weights per layer.

---

## 6. Getting Input Into the Encoder

Before any of this runs, the source sentence has to become numbers. This uses the embedding process from Core Concepts, plus the positional encoding from the same chapter, combined at the very bottom of the stack:

```
Input Sentence ("I am happy")
        ↓
   Token IDs
        ↓
Input Embeddings (n × 512)
        ↓             +  Positional Encoding (n × 512)
        ↓
Combined Representation
        ↓
   Encoder Block 1 → Block 2 → ... → Block 6
        ↓
   Final Encoder Output (z)
```

This particular embedding layer is called the **input embedding** — it converts only the *source* sentence. The decoder uses a second, separate embedding layer for the *output* sentence being generated, which we'll cover alongside the decoder itself.

---

## 7. Summary

- The encoder is a stack of **6 identical blocks**, each refining the previous block's output
- Each block has two sublayers: **multi-head self-attention**, then a **feed-forward network**
- Every sublayer is wrapped in **residual connection → layer normalization**
- Everything stays **512-dimensional** throughout, so the residual additions always work
- Encoder self-attention has **no masking** — every word can see every other word, in both directions
- The final output, `z`, is a fully contextualized representation of the entire input sentence — ready to be handed to the decoder

> **One-line insight:** Six identical blocks, each doing "attend, then think," gradually turn a sentence of independent words into a rich, context-aware representation — with residual connections and normalization quietly keeping the whole stack trainable.
