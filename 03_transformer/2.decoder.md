# The Decoder

*The encoder finished reading — its output `z` is a fully contextualized understanding of the input sentence. Now the writing team takes over: the decoder, generating the translation one word at a time, consulting the encoder's notes as it goes.*

---

## 1. Overview

Structurally, the decoder looks a lot like the encoder — another stack of **N = 6 identical blocks**, each refining the representation a little further. But it introduces two things the encoder didn't need:

1. An extra sublayer: **cross-attention**, which lets the decoder consult the encoder's output
2. A modified version of self-attention: **masked self-attention**, which stops the decoder from "peeking" at words it hasn't generated yet

---

## 2. The High-Level Flow

```
Encoder Output (z)
        │
        │  (feeds into every decoder block's cross-attention)
        ▼
┌───────────────────────────────────┐
│ Decoder Block 1                    │
│                                     │
│  Sublayer 1: Masked Self-Attention │
│       ↓  LayerNorm(x + Sublayer(x))│
│                                     │
│  Sublayer 2: Cross-Attention  ◄────┼── uses encoder output (z)
│       ↓  LayerNorm(x + Sublayer(x))│
│                                     │
│  Sublayer 3: Feed-Forward Network  │
│       ↓  LayerNorm(x + Sublayer(x))│
└───────────────────────────────────┘
        ▼
   Decoder Block 2  →  ...  →  Decoder Block 6
        ▼
   Final Output
```

Each of the 6 blocks contains all **three** sublayers — same "every block is a complete unit" rule from the encoder chapter applies here too.

---

## 3. Sublayer 1: Masked Self-Attention

**The problem it solves:** during training, the decoder is shown the *entire* target sentence at once (for efficiency). Left unchecked, it could cheat — "predicting" a word by simply looking ahead and copying it, instead of actually learning to generate it from what came before.

**The fix:** mask out every future position before the softmax step, forcing each position to only attend to itself and whatever comes *before* it:

| Generating step | Can attend to | Cannot see |
|---|---|---|
| 1 | `[START]` | everything after it |
| 2 | `[START]`, word₁ | everything after it |
| 3 | `[START]`, word₁, word₂ | everything after it |

**How the mask actually works, mechanically:** recall from Core Concepts that scores get passed through softmax before being used as weights. The trick is to set every "forbidden" future score to negative infinity *before* that softmax step:

```
Before softmax:  scores = [2.1, 1.8, -∞, -∞]

After softmax:
  e^2.1  = 8.16
  e^1.8  = 6.05
  e^(-∞) = 0.00   ← eliminated
  e^(-∞) = 0.00   ← eliminated

  final weights = [0.57, 0.43, 0.00, 0.00]
```

Because `e^(-∞) = 0`, those future positions contribute exactly **zero** to the output — not "close to zero," but mathematically impossible for any information to leak through. This guarantees prediction at position *i* can only ever depend on positions ≤ *i*.

---

## 4. Sublayer 2: Cross-Attention (Encoder–Decoder Attention)

This is the genuinely new sublayer the decoder has that the encoder doesn't — the actual bridge between the two floors of our office-building analogy:

```
Q  ←  comes from the DECODER (previous decoder sublayer)
K  ←  comes from the ENCODER output (z)
V  ←  comes from the ENCODER output (z)
```

The decoder's query effectively asks: *"given everything I've written so far, which parts of the original sentence matter right now?"* The encoder's keys and values — computed once, and reused at every single decoder step — provide the answer. There's no masking here; the decoder is allowed to look at the entire input freely, since the input sentence is fully known in advance. Only the *output* being generated needs the masking treatment above.

**Walking through it — translating "I am happy" → "मैं खुश हूँ":**

```
Generating "मैं":
  Q = decoder's current state
  K, V = encoder output for ["I", "am", "happy"]
  → attends most strongly to "I"     → produces "मैं"

Generating "खुश":
  Q = decoder's state (after "मैं" has been generated)
  K, V = same encoder output, unchanged
  → attends most strongly to "happy" → produces "खुश"
```

Notice the encoder's output doesn't change between these steps — it was computed once, and the decoder simply revisits it, asking a different question at each step of generation.

---

## 5. Auto-Regressive Generation (The Output Offset)

To train the decoder to generate one word at a time using only what came before, its input is deliberately **shifted right by one position** during training:

| Decoder Input | Expected Output |
|---|---|
| `[START]` | word₁ |
| `[START]`, word₁ | word₂ |
| `[START]`, word₁, word₂ | word₃ |

Combined with the masking from Sublayer 1, this setup — called **auto-regressive** generation — guarantees the model only ever learns to predict the next word from real, already-generated context, never by peeking at the answer.

---

## 6. Sublayer 3: Feed-Forward Network

The same position-wise FFN from the encoder chapter shows up again here, unchanged in mechanism (expand 512 → 2048, ReLU, compress back to 512). The only difference is its position in the block — it now comes *after two* attention steps instead of one:

```
Encoder block:  Self-Attention           → FFN
Decoder block:  Masked Self-Attention → Cross-Attention → FFN
```

The division of labor still holds: the two attention sublayers decide **what information matters** (from the output-so-far, and from the source sentence), and the FFN decides **how to transform** that gathered information into something more useful for the next block.

---

## 7. Getting Output Tokens Into the Decoder

Just like the encoder has its input embedding, the decoder has its own **output embedding** — converting whatever's been generated *so far* into vectors, using the exact same embedding mechanics from Core Concepts:

```
[START] मैं खुश
        ↓
 Decoder (Output) Embeddings
        ↓  +  Positional Encoding
        ↓
 Decoder Block 1 → ... → Block 6
```

This is the "second embedding layer" mentioned back in the encoder chapter — same underlying mechanism, just applied to the sentence being written instead of the sentence being read.

---

## 8. Encoder vs. Decoder, Side by Side

| | Encoder | Decoder |
|---|---|---|
| Number of blocks | 6 | 6 |
| Sublayer 1 | Self-Attention | **Masked** Self-Attention |
| Sublayer 2 | Feed-Forward | **Cross-Attention** |
| Sublayer 3 | — | Feed-Forward |
| Residual + LayerNorm | Yes, every sublayer | Yes, every sublayer |
| Can see future tokens? | Yes (whole input at once) | No — masked |
| Model dimension | 512 | 512 |

---

## 9. Putting All Three Forms of Attention Together

We've now met every form of attention the Transformer uses. Here's the complete picture in one place:

| | Encoder Self-Attention | Decoder Self-Attention | Cross-Attention |
|---|---|---|---|
| Q comes from | Encoder | Decoder | Decoder |
| K, V come from | Encoder | Decoder | **Encoder** |
| Masking | None | Future positions masked | None |
| Can see | All input positions | Past output positions only | All input positions |
| Purpose | Build full understanding of input | Generate output without seeing ahead | Bridge input understanding to output generation |
| Location | Encoder, sublayer 1 | Decoder, sublayer 1 | Decoder, sublayer 2 |

---

## 10. The Full Pipeline, End to End

Tracing "I am happy" all the way to "मैं खुश हूँ":

```
Input: "I am happy"
          │
          ▼
  Encoder Self-Attention (× 6 blocks)
    "I", "am", "happy" freely attend to each other
    → builds rich, bidirectional understanding → z
          │
          ▼
  ═══════════════ handoff to decoder ═══════════════
          │
          ▼
  Decoder Masked Self-Attention
    [START] → मैं → खुश → हूँ
    each step attends only to its own past
          │
          ▼
  Cross-Attention
    decoder queries consult encoder's z
    "which part of the input do I need right now?"
          │
          ▼
  Feed-Forward Layer
          │
          ▼
  Output: "मैं खुश हूँ"
```

---

## 11. Summary

- The decoder mirrors the encoder's 6-block structure, but adds a third sublayer: **cross-attention**
- **Masked self-attention** guarantees the decoder can never use information from words it hasn't generated yet — enforced not just by convention, but mathematically, via `-∞` scores zeroing out in softmax
- **Cross-attention** is the actual bridge between encoder and decoder — decoder queries, encoder keys and values
- The **output offset** during training is what makes auto-regressive generation possible
- Every sublayer still uses **residual connections + layer normalization**, and everything stays **512-dimensional**

> **One-line insight:** The decoder writes one word at a time, blind to the future by design — and at every single step, it's allowed to glance back at the encoder's complete understanding of the input to decide what comes next.
